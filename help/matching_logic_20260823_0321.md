# 매칭 프로세스 및 아키텍처 명세서

본 문서는 매칭 시스템의 전체 동작 원리와 AI 연동 아키텍처를 정의합니다.

## 1. 매칭 기준 자료 (DB 초기화)
시스템 구동 시, 회원 매칭을 위한 6대 카테고리 총 194개의 기준 단어가 DB(matching_trait_reference)에 세팅됩니다.
- 외모/피지컬 (30개)
- 직업/경제력 (30개)
- 가치관/결혼관 (30개)
- 라이프스타일 (50개)
- 성격/MBTI (32개)
- 연애 스타일/다이내믹스 (22개)

더미 3000명의 회원에게는 이 194개 단어 중 일부에 대해 가중치(0~100)가 부여된 JSON 데이터가 member_trait 테이블에 저장됩니다.

## 2. 매니저 매칭 시도 (Front-end)
관리자(매니저)는 매칭하기 화면에서 최대 3개의 키워드(예: "글래머", "도파민", "낮져밤이")를 입력합니다.
매칭 결과로 뽑아낼 남녀 각각의 인원수(예: 남 5명, 여 5명)를 설정합니다.
확인 버튼을 누르면 API 요청(POST /api/matching/execute)이 백엔드로 전송됩니다.

## 3. 동적 AI 스위칭 및 필터링 (Dynamic AI Routing)
백엔드는 DB의 ai_config 테이블을 조회하여 현재 활성화된 AI(MOCK, GEMINI 등)를 결정합니다.

만약 Gemini AI가 활성화되어 있다면:
- 매니저가 입력한 키워드와 194개의 기준 단어 풀을 Gemini API로 전송합니다.
- Gemini는 프롬프트를 분석하여 194개 단어 중 가장 의미가 가까운 단어들만 선별하고 0~100의 가중치를 매긴 JSON 형태로 응답합니다.

## 4. 벡터 거리 기반 타겟팅 연산 (KNN 알고리즘 응용)
AI가 반환한 가중치 맵(타겟 가중치)을 전체 회원 데이터와 비교 연산합니다.
- 전체 3000명 회원의 JSON 가중치 데이터를 순회합니다.
- 타겟 단어들에 대해 절대값(타겟 점수 - 회원 점수)을 계산하고 이를 모두 합산하여 오차점수(Diff Score)를 산출합니다.
- 오차점수가 0에 가까울수록 매니저가 입력한 이상형과 완벽하게 일치하는 회원입니다.

## 5. 인원수 분배 및 정렬
산출된 오차점수를 기준으로 남녀 회원을 각각 오름차순(오차가 적은 순) 정렬합니다.
프론트엔드에서 요청한 남녀 인원수만큼 최상위 회원을 잘라내어 반환합니다.

## 6. 매칭 이력(로그) 저장 및 AI 안전망 감사 (Auditing)
모든 매칭 시도는 결과에 상관없이 그 즉시 추적 로그로 DB(matching_history)에 기록됩니다.
- 검색을 시도한 매니저 이름
- 매니저가 입력한 검색 키워드 텍스트
- AI가 변환해 낸 기준 단어 및 가중치 JSON
- 시도 날짜 및 시간

[AI 안전 필터 예외 처리 및 감사 기능]
만약 매니저가 성적이거나 불법적인 노골적 텍스트를 입력하여 구글 Gemini의 1차 안전 필터(Input Safety Filter)에 의해 에러(차단)가 발생할 경우:
- 서버는 죽지 않고 즉시 예외를 캐치(Try-Catch)합니다.
- 해당 검색 시도를 matching_history 테이블에 status = ERROR_BLOCKED 상태로 강제 저장합니다.
- 프론트엔드 화면(매칭 내역 관리)에서는 이 차단된 내역을 붉은색 배경과 경고 아이콘으로 하이라이트 처리하여 보여줍니다.
- 이를 통해 최고 관리자(Admin)는 어떤 매니저가 시스템을 악용하거나 부적절한 단어를 검색했는지 100% 추적하고 모니터링할 수 있습니다.
