# 담당자(Manager) 인증 및 계정 관리 로직 명세서

본 문서는 프로젝트의 담당자(Manager) 회원가입, 로그인, 그리고 비밀번호 재설정 기능이 프론트엔드와 백엔드 간에 어떻게 구현되어 있고, 어떤 함수를 통해 검증 및 분기 처리되는지에 대해 상세히 기술합니다.

---

## 1. 회원가입 (Signup)

### 주요 소스 파일
- **프론트엔드:** `SignupScreen.tsx` (`handleSignup`, `validateForm`)
- **백엔드:** `ManagerController.java` (`POST /api/managers/register`), `ManagerService.java` (`register`)

### 프론트엔드 검증 로직 (`validateForm()`)
사용자가 폼을 작성하고 가입하기 버튼을 클릭하면, 먼저 프론트엔드에서 아래 조건들을 검증합니다. 통과하지 못하면 서버로 요청을 보내지 않고 바로 알림(Popup)을 띄웁니다.

1. **빈 값 체크:** 
   - 폼 데이터 중 빈 값이 하나라도 있을 경우
   - 알림 메시지: `모든 필드를 입력해주세요.`
2. **사번 유효성 체크:**
   - 사번(`empNo`) 길이가 정확히 8자리가 아닌 경우
   - 알림 메시지: `사번은 8자리여야 합니다.`
3. **비밀번호 유효성 체크:**
   - 비밀번호(`password`) 길이가 6자 이하인 경우
   - 알림 메시지: `비밀번호는 7자 이상이어야 합니다.`
4. **생년월일 유효성 체크:**
   - 브라우저 달력 컴포넌트 오류 또는 존재하지 않는 날짜(예: 2월 30일)가 들어온 경우
   - 알림 메시지: `유효하지 않은 생년월일입니다. 달력에 있는 날짜를 선택해주세요.`

### 백엔드 검증 및 로직
프론트엔드 검증을 통과하면 서버의 `POST /api/managers/register` 엔드포인트가 호출됩니다.

1. **중복 검사 (`ManagerService.register`):**
   - 아이디 중복 체크 (실패 시 `IllegalArgumentException` 발생) -> 에러 응답
   - 사번 중복 체크 (실패 시 `IllegalArgumentException` 발생) -> 에러 응답
2. **데이터 저장:**
   - 보안을 위해 `SecurityUtil.hashPassword()`를 통해 비밀번호를 암호화(SHA-256 등)하여 DB에 저장.
   - 이름 등 정보의 경우 마스킹 처리가 필요할 시 `SecurityUtil.maskName()` 활용.

### 최종 응답 메시지 (프론트엔드 노출)
- **성공 시:** `회원가입이 완료되었습니다. 로그인 해주세요.` (로그인 화면으로 리다이렉트)
- **에러 시 (400 Bad Request):** 백엔드에서 반환된 메시지(예: "이미 존재하는 아이디입니다." 등)를 그대로 화면에 띄웁니다.

## 2. 로그인 (Login)

### 주요 소스 파일
- **프론트엔드:** `LoginScreen.tsx` (`handleLogin`)
- **백엔드:** `ManagerController.java` (`POST /api/managers/login`), `ManagerService.java` (`login`)

### 프론트엔드 검증 로직
1. **빈 값 체크:**
   - 아이디(`username`) 또는 비밀번호(`password`)가 입력되지 않은 경우
   - 알림 메시지: `아이디와 비밀번호를 모두 입력해주세요.`

### 백엔드 검증 및 로직
1. **계정 확인 (`ManagerService.login`):**
   - 넘겨받은 아이디로 DB를 조회. 없으면 `IllegalArgumentException("아이디 또는 비밀번호가 올바르지 않습니다.")` 발생.
   - 계정이 있다면 저장된 해시 비밀번호와 입력된 비밀번호(해시 처리 후) 비교. 불일치 시 예외 발생.

### 성공 흐름 및 상태 관리
- **성공 시:** 
  - 백엔드가 담당자의 식별자(ID)와 이름을 반환합니다.
  - 프론트엔드는 이를 브라우저 `localStorage`에 각각 `managerId`, `managerName`으로 임시 저장합니다.
  - 이후 `/main` (메인 화면)으로 리다이렉트합니다.
- **에러 시:** 
  - 백엔드에서 반환한 에러 메시지(`아이디 또는 비밀번호가 올바르지 않습니다.`) 팝업을 띄웁니다.

## 3. 비밀번호 재설정 (Password Reset)

비밀번호 재설정은 사용자 편의와 검증을 위해 **2단계 프로세스**로 구현되어 있습니다.

### 주요 소스 파일
- **프론트엔드:** `ResetPasswordScreen.tsx` (`handleVerifyUsername`, `handleResetPassword`)
- **백엔드:** `ManagerController.java` (`GET /check-username`, `POST /reset-password`)

### 1단계: 아이디 검증 (`handleVerifyUsername`)
먼저 아이디의 유효성을 체크하여, 등록된 사용자만 비밀번호 입력창을 볼 수 있도록 합니다.

1. **프론트엔드 빈 값 체크:** 
   - 아이디를 입력하지 않고 확인 버튼을 누를 경우
   - 알림 메시지: `아이디를 입력해주세요.`
2. **백엔드 검증 (`GET /api/managers/check-username?username=...`):**
   - 백엔드는 단순히 해당 아이디가 DB에 있는지 `boolean` 값으로 반환.
3. **분기 처리 결과:**
   - **아이디 없음 (false):** `해당 아이디로 조회되는 정보가 없습니다.` 알림 노출 후 입력 초기화
   - **아이디 존재 (true):** `isUsernameVerified` 상태를 true로 변경하고, 화면에 "확인 완료된 아이디입니다." 텍스트와 함께 **2단계 비밀번호 폼(새 비밀번호, 비밀번호 확인)** 노출.
   - *참고:* 이미 인증된 상태에서 사용자가 다시 아이디 입력칸을 수정하려고 하면 즉시 인증 상태가 초기화되어 확인을 다시 받아야 합니다.

### 2단계: 비밀번호 변경 (`handleResetPassword`)
아이디 검증이 끝난 후 새로운 비밀번호를 입력하고 "비밀번호 변경하기"를 누를 때의 로직입니다.

1. **프론트엔드 검증:**
   - **빈 값 체크:** `모든 항목을 입력해주세요.`
   - **1단계 우회 방지 체크:** `먼저 아이디 확인을 진행해주세요.`
   - **비밀번호 길이 체크:** `새 비밀번호는 7자 이상이어야 합니다.`
   - **비밀번호 일치 체크:** 폼의 새 비밀번호와 새 비밀번호 확인란이 다를 경우 `새 비밀번호와 비밀번호 확인이 일치하지 않습니다.`
2. **백엔드 로직 (`POST /api/managers/reset-password`):**
   - 아이디와 새로운 비밀번호를 받아, 기존 비밀번호를 새로운 비밀번호의 암호화(해시) 값으로 덮어씁니다(`ManagerService.resetPassword`).
3. **최종 응답 메시지:**
   - **성공 시:** `비밀번호가 성공적으로 변경되었습니다. 새 비밀번호로 로그인해주세요.` (팝업 후 로그인 화면 리다이렉트)
   - **에러 시:** 에러 원인 메시지 알림
