# 매칭 로직 전체 흐름도 및 아키텍처 정리 문서

이 문서는 시스템 내에 구축된 매칭 시스템의 동작 원리 및 AI 연동 로직을 상세히 정리한 문서입니다.

## 1. 매칭 기준 자료 (DB 초기화)
시스템이 시작될 때, 회원들의 성향을 평가하기 위한 150개의 기준 단어가 DB(matching_trait_reference)에 저장됩니다.
구분값은 3가지로 나뉩니다.
- 외모 (50개) : 강아지상, 고양이상, 청순한 등
- 성격 (50개) : 다정한, 활발한, 차분한 등
- 이상형 (50개) : 연봉높은, 운동하는, 전문직 등

또한 모든 3000명의 목업 회원들에게도 위 150개 단어 중 일부에 대해 가중치(0~100) 점수가 부여된 JSON 데이터가 member_trait 테이블에 저장됩니다.

## 2. 매니저의 매칭 시도 (Front-end)
관리자(매니저)는 매칭하기 화면에서 최대 3개의 주제어(예: "강아지상", "연봉높은", "운동하는")를 입력합니다.
매칭 시작 버튼을 누르면 팝업이 뜨며 매칭할 대상의 "남성 인원 수", "여성 인원 수"를 입력합니다.
확인을 누르면 백엔드로 API 요청(POST /api/matching/execute)이 전달됩니다.

## 3. 동적 AI 가중치 추출 (Dynamic AI Routing)
백엔드는 즉시 DB의 ai_config 테이블을 조회하여 현재 활성화된 AI(MOCK, GEMINI 등)가 무엇인지 확인합니다.

현재는 개발 및 테스트를 위해 비용이 발생하지 않는 임시 MOCK AI가 동작합니다.
이 MOCK AI는 사용자의 입력과 무관하게 150개의 기준 단어 중 무작위로 5~8개의 단어를 선택하여 50~100 사이의 무작위 가중치를 반환합니다.

향후 Gemini AI로 스위칭할 경우 다음과 같이 동작합니다.
- 프롬프트와 매니저의 입력 주제어 3개, 그리고 150개의 기준 단어 목록을 Gemini API에 전송합니다.
- Gemini는 문맥을 파악하여 150개 중 가장 관련 있는 단어들만 추출하고 0~100점의 가중치를 매겨 순수 JSON 형태로 응답합니다.

## 4. 수학적 거리 기반 타겟 추출 연산 (KNN 알고리즘 유사 방식)
AI가 반환한 가중치 데이터(타겟 가중치)를 기반으로 전체 회원의 데이터와 비교 연산을 수행합니다.
- 전체 3000명 회원의 JSON 가중치 데이터를 순회합니다.
- 타겟 단어들에 대해 (타겟 점수 - 회원 점수)의 절대값을 구하고 모두 합산하여 차이값(Diff Score)을 계산합니다.
- 차이값이 0에 가까울수록 매니저가 입력한 이상형에 정확히 부합하는 회원입니다.

## 5. 인원 분할 및 추출
계산된 차이값을 기준으로 남성 회원과 여성 회원을 각각 오름차순(차이가 적은 순)으로 정렬합니다.
매니저가 UI에서 설정했던 "남성 인원", "여성 인원" 수 만큼 최상위 회원들을 잘라냅니다. (예: 남 5명, 여 5명)

## 6. 매칭 이력(로그) 저장
최종적으로 매칭 연산이 종료되면, 이 통계 자료와 로그를 DB(matching_history)에 즉각 저장합니다.
- 매칭 시도 매니저 이름
- 매니저가 입력한 검색 주제어 리스트
- AI가 추출한 최종 기준 단어 및 가중치 결과값 JSON
- 시도된 날짜 및 시간

이 기록은 관리자 화면의 "매칭 이력 조회" 메뉴를 통해 언제든 투명하게 열람할 수 있습니다.
