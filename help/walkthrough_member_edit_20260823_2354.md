# 회원 정보 수정 및 등록 기능 개선 내역

본 문서는 회원 등록 및 수정 기능과 관련하여 적용된 주요 변경 사항, 버그 픽스, 정책 변경 내역을 기록합니다.

## 1. UI 및 접근성 개선
- **수정 취소 버튼 추가:** 회원 상세 정보 화면에서 수정 모드로 진입했을 때, 우측 상단에 `수정 취소` 버튼을 옅은 빨간색으로 배치하여 사용자 인터페이스의 가시성을 높였습니다. 
- **자동 팝업 띄우기 (상태 유지):** 수정 화면에서 [수정 취소]를 누르거나 [회원 정보 수정 완료]를 눌러 리스트로 돌아갈 때, 기존에 보고 있던 회원의 상세 정보 팝업이 다시 자동으로 열리도록 `location.state`를 활용하여 개선했습니다.
- **디폴트 체크박스 설정:** 매니저가 회원 조회 화면에 진입할 때, '내 담당회원만 보기' 체크박스가 기본적으로 체크되어 있도록 초기 상태(`true`)를 변경했습니다.

## 2. 권한 및 보안 (어뷰징 방지)
- **수정 권한 제한:** 회원의 정보는 **최초에 해당 회원을 등록한 매니저**이거나 **관리자(Admin)**인 경우에만 수정할 수 있도록 백엔드 권한 체크 로직을 강화했습니다.
- **수정 횟수 제한 (일일 3회):** 과도한 정보 수정으로 인한 AI 프로파일링 API 비용 증가 및 남용을 방지하기 위해, 하루 최대 수정 횟수를 3회로 제한했습니다. (`updateCountToday` 필드 도입)

## 3. 백엔드 버그 픽스 및 안정화
- **LazyInitializationException (500 에러) 해결:** 수정 폼에 기존 회원 정보를 불러올 때 발생하는 Jackson 직렬화 에러를 해결하기 위해 `Member.java`와 `Manager.java` 엔티티에 `@JsonIgnoreProperties({"hibernateLazyInitializer", "handler"})`를 추가했습니다.
- **AI 프로파일링 데이터 잘림 현상 해결:** AI 프로파일링 수행 결과 텍스트가 매우 길어질 수 있는 점을 고려하여, DB의 `ai_remarks` 컬럼 타입을 255자 제한의 `VARCHAR`에서 무제한 길이의 `TEXT` 타입으로 변경했습니다.
- **신규 회원 등록 시 Null 제약조건 예외 해결:** Lombok의 `@Builder`가 엔티티에 설정된 기본값(예: `updateCountToday = 0`)을 무시하는 문제를 해결하기 위해, 해당 필드에 `@Builder.Default` 어노테이션을 추가하여 신규 생성 시에도 정상적으로 0으로 초기화되도록 수정했습니다.

## 4. 프론트엔드 버그 픽스
- **타입스크립트(TypeScript) 엄격한 타입 검사 에러 해결:** 파일 업로드 시에 사진 데이터를 관리하는 `loadedPhotos` 배열의 타입을 명시(`{ id: number; url: string; rawUrl: string; isExisting: boolean; file?: File }[]`)하여, 배포/빌드 시 발생하는 에러 화면(오버레이) 블로킹 이슈를 해결했습니다.
